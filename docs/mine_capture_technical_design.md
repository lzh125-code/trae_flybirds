# “我的”栏目多语言采集与识别技术设计

- 版本：1.11
- 日期：2026-11-13
- 状态：已确认，按本文实施
- 需求基线：[mine_capture_requirements.html](mine_capture_requirements.html)

本文定义实现和验证方案。现有 `flybirds_demo/pscript/crawl_mine_lang.py`、`scan_capture_text.py`、`compare_lang_text.py` 仅作为实现基线，不代表本文设计已经全部落地。实施状态必须以逐项验收结果为准。

## 1. 设计原则

1. 需求编号是实现和验收的共同索引，不允许代码行为与需求文档各自演化。
2. 每个页面、Tab 和弹层先进行只读身份核验；新页面必须先预扫描、生成验证计划并恢复初始状态，再开始正式截图或验证动作。
3. 全局按业务身份和页面自身状态去重；来源路径不参与页面身份去重，但作为导航关联边独立保存，同模板不同业务数据不得误判为重复。
4. 中文、日文各以持久 JSON 页面地图为事实源，Mermaid 仅作展示；每轮保存独立快照。地图查询先于整套预扫描和翻页，证据有效的完成页跨轮复用。
5. 以页面真实状态、计划核销、有效截图和清单记录判断完成，不以脚本退出码或截图总数判断完成。
6. 同一台 Android 设备同一时间只运行一个采集任务，中日文顺序执行；同一语种地图不并发写入。
7. 动作按“可逆性”分级，而不是按名称中的危险词一刀切：页面入口默认 `allow_entry`，一律进入首屏取证；退出登录、注销账号、结束会话等账号/会话终止动作 `deferred`，在本轮全部采集结束后统一执行且不确认；保存、提交、发送验证码、支付/买卖/下单、删除确认、清空、清除数据/缓存、卸载、强制停止、切换语言 `hard_blocked`，任何情况下不执行。页面进入权限与页内动作权限分离；允许进入首屏和试输入占位内容，不代表允许保存、提交或切换状态。
8. 资源限制可以终止采集，但必须把未执行范围写成明确的 `skipped` 或 `failed` 并计入未完成项，不能静默 `break`。
9. 四层限制属于以任意业务页面为起点的扩展任务；页面自身覆盖与四层扩展覆盖分别记录。`relative_depth` 可随扩展起点变化，`page_key` 和页面有效证据不随路径重建。

## 3. 运行配置与设备准备

### 3.1 配置项

| 配置 | 目标约定 |
| --- | --- |
| `CRAWL_LANG` | `zh-CN` 或 `ja-JP`；一次运行只使用一种语言 |
| `CRAWL_ROOTS` | 可选一级入口过滤；`home` 表示只采首页固定项（见 5.8）；完整验收必须覆盖全部入口 |
| `CRAWL_MAX_*` / `CRAWL_BUDGET_MIN` | 只作为资源保护，不得成为静默漏采理由 |
| `CRAWL_PAGE_MIN` | 单页采集时间上限（默认 20 分钟）；超时把该页未执行目标写 `skipped + skip_class=resource`，避免营销/H5 页面反复刷新拖垮整轮 |
| `CRAWL_DEFERRED` | 轮末延迟项开关：`auto` 仅全量轮执行，收尾轮显式 `1` |
| `CRAWL_FORCE_REFRESH` | 可选强制刷新；即使节点完成且证据有效也重新采集，但不得删除上一次有效证据 |
| 包名 / Activity | 运行前确认当前安装目标；当前“我的”采集基线为 `com.wetrade.crm.demo` / `com.wetrade.crm.MainActivity` |
| 设备 | 默认 `emulator-5554`；连接后读取真实分辨率，不套用其他设备的固定尺寸 |
| 本轮输出目录 | `app_page_captures/lang/<语言>/<时间戳>/` |
| 持久地图 | `app_page_captures/lang/<语言>/page_map.json` 与自动生成的 `page_map.mmd`；每轮快照保存在本轮目录 |

### 3.2 准备规则

- 固定竖屏并读取当前分辨率，坐标统一使用归一化值。
- 使用显式 Activity 启动；本任务不清除 App 数据。
- 确认当前已登录且位于“我的”首页；无法确认时停止并记录，不尝试登录或切换账号。
- 语言切换作为独立准备步骤：进入设置的语言项、选择目标语言、回到“我的”并验证目标语言特征。完整采集结束后恢复原语言。
- 通用遍历中的语言入口固定为 `NO_EXPAND`，避免采集中途改变语言导致同次结果混杂。若入口文案变化导致误入语言页，以页面内容兜底：同时出现 2 个及以上语言名（简体中文/繁體中文/日本語/English/한국어）即判定为语言选择页，只保留首屏截图，不点击任何选项。
- 恢复到桌面或 PocoService 时不再继续 BACK，而是重新拉起 App 后重新核验；避免连续返回把 App 退出后整条恢复链失败。

## 4. 页面语义与稳定标识

### 4.1 控件读取

- 同时读取 `name`、`desc`、`text`，剔除不可见节点、系统状态栏、零尺寸节点和资源类名。
- 无文字图标结合固定区域、节点几何、`resource-id`/可点击属性及最近可点击祖先定位，不把短文案作为必要条件；坐标只作为按真实分辨率校准后的 fallback，并在清单记录定位来源。
- 包含匹配命中多个节点时选择面积最小者，避免点击全屏父容器。
- 加载/滚屏稳定性指纹只归一化已确认的动态噪声，并过滤底部导航的无障碍描述；去重使用的全页内容指纹必须保留客户、订单、金额、日期等业务差异，禁止统一替换全部数字。两类指纹分开计算、分开使用。
- 页面切换判定使用剔除时钟（`HH:MM`、`HH:MM:SS`）后的文本集合，避免时钟变化把“点击未跳转”误判成新页面。判定为未跳转时记 `skipped=点击无跳转`，不为该目标新建页面目录或截图；页内 Tab 切换只在确有内容变化时登记，不允许同一帧以不同名称重复落盘。
- 证据告警（只写入 `coverage_report.json` 的 `warnings`，不改变 `complete`）：`first_screen_missing` 表示页面目录缺少 `001_逐屏.png` 首屏；`same_image_different_page` 表示两个不同页面身份的首屏像素级相同（感知哈希完全一致），提示存在误拍或复用错图。
- 截图前连续两轮采集页面文案；指纹一致且无加载标记后才保存。
- RN、Flutter、canvas、H5 统一通过 `page_items()` 提供文本、几何、可点击属性和来源；稳定文案少于 3 条或没有可用控件时以 OCR 补充。发现与执行重定位必须复用同一取数层，目标来源统一为 `tree|ocr|fixed`。
- 页面变化按控件指纹变化 OR 页面图像差分大于 1% OR OCR 文本集合变化判断；canvas 等文本不足页面不得跳过图像判定。

### 4.2 跨语言页面/交互标识

仅在清单中保存本地化 `navigation_path` 无法稳定配对中日文结果。目标实现增加语言中立的 `page_id`：

```text
mine
mine.notifications
mine.customer_service
mine.wallet
mine.wallet.visibility
mine.agent.ib_plan
mine.agent.customer_funds
mine.home.carousel[1]
mine.home.carousel[1].open
mine.funds.tab[deposit].screen[2].record[4]
mine.funds.screen[2].filter[1].option[2]
mine.copytrade.tab[3]
```

- SC-02 的十个一级入口沿用固定 ID：`agent`、`profile`、`copytrade`、`points`、`settings`、`club`、`deposit`、`withdraw`、`transfer`、`funds`；SC-04 另补充 `notifications`、`customer_service`、`wallet` 三个首页入口，由 AC-09 单独核销。
- 代理专区下级固定 ID 为 `ib_plan`、`commission`、`customers`、`customer_orders`、`customer_funds`、`account_link`；中文名称按 SC-04 登记，日文别名在实施前从真实页面校准，不编造翻译。
- 头像、用户名、会员徽标、IB 徽标分别使用 `mine.home.avatar.probe`、`mine.home.username.probe`、`mine.home.membership_badge.probe`、`mine.home.ib_badge.probe`，与确定可点击的页面入口区分。
- 资金记录页以实际到达页面的 ID 为前缀，追加 `customer_selector`、`tab[deposit|withdraw|transfer]`、`month`、`filter`、`screen[n]`、`record[n]` 和 `record[n].detail`，不把“全部客户”硬编码成唯一导航来源。
- 已知下级入口使用双语别名映射到同一语义 ID。未登记入口按父页面中的发现顺序生成临时 ID；临时 ID 可用于本次追溯，但跨语言配对必须标为待复核，不能假装是确定匹配。
- 交互 ID 由页面 ID 加交互类型和序号组成；选项截图记录实际选项文案，但不把本地化文案作为唯一键。

固定目标注册表每项至少保存 `target_id`、双语别名、相对区域、动作类型、预期结果、恢复规则和安全规则。固定目标未命中时直接生成 `failed` 覆盖项，动态识别结果只能补充，不能删除注册表中的目标。

## 5. 页面预扫描、计划与执行

### 5.1 身份核验与只读预扫描门禁

每个页面、切换后的 Tab 和新打开的弹层先查询持久地图，再决定是否只读预扫描。四个首页内嵌区块只处理其真实可见的一屏。预扫描期间只允许读取控件树、几何和图像状态，以及为发现内容而纵向滚动；禁止点击、横向滑动和保存正式采集截图。不得沿用“弱身份页面每次先完整翻页、最后才查注册表”的执行顺序。

```text
发现来源页目标时：
  由 language + source_page_key + target_id + 归一化定位特征 + expected_view_state
  生成 route_key，并查询关联边及其 target_page_key
  若目标 status=done 且证据有效，且未指定 CRAWL_FORCE_REFRESH：
    来源目标记录 skipped=已完成页面、target_visit_key、duplicate_of 和 map_reason
    页面自身不重新预扫描、不正式截图、不翻页
    当前 expansion_key 尚未完成且需要覆盖其第2～4层后代时：
      复用已知计划和关联边定位入口并继续下钻，不重新采集当前页面自身
  若目标 status=collecting：
    记录循环原因和首次导航路径，禁止递归
  否则按安全计划进入或处理目标

首次进入未知页面 / Tab / 弹层：
  等待加载稳定，只读取首屏 page_id、页面类型、business_key 和 initial_view_state
  形成 resolved_page_key；page_key 与现有 visit_key 同义，清单仍沿用 visit_key 字段
  强业务身份命中 done 且证据有效：立即复用，不启动全页预扫描
  强业务身份命中 collecting：阻断循环并恢复来源页
  弱身份：先匹配持久入口签名和已知 route_key；能确定完成节点则立即复用
  只有从未见过且无法可靠判新的弱身份页面，才允许一次有记录的完整预扫描来建立身份
  新页面或待补采页面：
    节点写 collecting，记录当前 run_id 和首次/当前导航路径
    回到顶部，screen=1，逐屏只读发现并登记固定及动态目标
    没有新内容则到底；长列表最多 3 屏，达到上限按 scroll_capped 收口
    资源耗尽必须写 survey_status=incomplete（长列表上限收口除外）
    没有强业务键时计算全页内容指纹并补全 resolved_page_key
    持久化 survey_status、验证计划、页面节点和入口关联边
    恢复 initial_view_state，回到顶部并校验状态
    预扫描完成后才允许正式截图和执行计划

从子页面返回来源页：
  调用 restore_only(parent_page_key, initial_view_state, screen_index)
  只核验来源身份并恢复 Tab、筛选和滚动位置，不调用 visit_page/survey
```

- 固定名单核销优先于动态发现；同一目标被两种方式命中时合并，不重复执行。固定目标未命中仍保留并写入 `failed`，不能从计划中删除。
- 以同一 `visit_key` 内的 `target_key` 避免连续两屏重复登记候选目标；若定位特征尚未稳定，先保留候选并待身份核验后合并，不得仅用 `(page_id, target_id)` 作为跨页或跨轮唯一键。交易记录以稳定业务特征形成 `business_key`，列表位置只用于当次定位，不参与跨模块页面去重。
- 预扫描只登记横向可滑动区域、可见标签和轮播 `n/m`，不通过横滑猜测内容。轮播卡片的“打开”目标只登记不展开（可能进入持续刷新的营销页），三种状态和恢复仍必须采集；未识别到指示器时由执行阶段实时识别并在失败时写明原因，不在预扫描提前判失败。执行阶段揭示的新标签或新区域必须先补充预扫描和计划，再进行点击。
- 下拉选项和弹层内容在父页面预扫描时只登记“打开”目标；面板打开后先进行身份核验，新弹层再预扫描并采集展开态和选项结果。
- 加载失败或预扫描中断时标记 `survey_status=failed/incomplete`，不得把后续截图计为完整页面覆盖。
- 长列表页（含消息中心、会员俱乐部、常见问题、资金记录、代理专区、跟单社区等连续列表）纵向预扫描最多 3 屏（`CRAWL_LIST_SCREENS`，默认 3）。第 3 屏后仍有新内容时写 `scroll_capped=true` 和 `scroll_note`，按已采证据收口为 `survey_status=complete`，页面可判 `done`；该提示属于 warning，只在本轮覆盖报告保留，不得据此把页面记为 `failed`。

### 5.2 持久页面地图、入口关系与跨模块去重

各一级入口不得分别维护互不共享的页面列表。现有内存 `registry` 只保留为运行期索引，启动时从本语种 `page_map.json` 加载，状态变化后同步持久化。清单继续保留来源 `visit_key`、目标 `target_visit_key` 和本地化 `navigation_path`，但页面关系必须独立写入 `edges`，不能再散落在父子上下文里。

```text
page_key = language + "|" + page_id + "|" + business_key + "|" + stable_view_state_json
route_key = language + "|" + source_page_key + "|" + target_id + "|" + normalized_locator + "|" + expected_view_state
edge_key = SHA256(route_key)

PAGE_MAP = {
  schema_version: 1,
  language: zh-CN | ja-JP,
  updated_at: 最近原子写入时间,
  nodes: {
    page_key: {
      page_id, business_key, view_state, title,
      status: discovered | collecting | done | partial | failed | blocked,
      first_navigation_path, first_seen_at, last_seen_at, last_error, attempts,
      entry_fingerprint: 用于弱身份候选匹配的首屏归一化指纹,
      last_valid_capture: {
        run_id, completed_at, plan_ref, coverage_ref,
        screenshots: [{path, screen_index, view_state, fingerprint}]
      },
      evidence: 历次有效截图引用，不因新一轮失败而删除
    }
  },
  expansions: {
    expansion_key: {
      root_page_key, depth_limit: 4,
      status: discovered | collecting | done | partial | failed,
      last_run_id, last_valid_coverage_ref, last_error
    }
  },
  edges: {
    edge_key: {
      source_page_key, target_page_key, target_id, route_key,
      label, action, source: tree | ocr | fixed,
      locator_summary, first_seen_at, last_seen_at,
      last_run_id, last_run_status
    }
  }
}
```

节点唯一不等于关联边唯一。多个不同入口到达消息主页时，只要 `route_key` 不同，就必须分别保留多条入边，目标仍指向同一个消息主页 `page_key`；同一入口反复到达具有相同 `route_key`，只更新该边的 `last_seen_at`、`last_run_id` 和 `last_run_status`，不重复建边。子页执行 `restore_only` 返回消息主页只记录恢复结果，不新增一条业务入口边，也不触发消息主页重新预扫描或翻页。

`page_key` 与 `visit_key` 使用同一身份定义，避免地图和清单出现两套去重口径。身份计算顺序固定为：加载完成后的稳定页 `page_id` → 经过明确白名单归一化且非空的业务键 → Tab/筛选等自身状态。`view_state` 包含 `customer`、记录类型、筛选条件等影响业务内容的维度；未读数、金额、日期等已确认动态噪声按页面类型归一化。只有这些身份信息仍为空且通过单例规则检查模板后，才使用完整页面内容指纹，禁止只凭相似模板去重。

状态与动作含义固定如下：

- `discovered`：已发现节点或关联，但尚未形成完整采集结果。
- `collecting`：本轮正在预扫描或执行；重复到达必须阻断循环。启动时发现上一次遗留的 `collecting`，转为 `partial` 并记录中断原因。
- `done`：页面自身覆盖门禁全部通过且 `last_valid_capture` 证据有效，允许跨轮 `skipped_done`；不代表任意起点的四层扩展均已完成。
- `partial`：预扫描到底失败、预算不足、证据不全或覆盖门禁未通过；后续必须补采。
- `failed`：定位、执行或恢复失败；允许按既有不同入口重试一次规则处理，同一入口不重复重试。
- `blocked`：安全策略禁止进入或操作，只保留父页或安全边界证据；不得伪装成正常 `done`。
- `skipped_done`：仅是本轮快照和来源目标的复用结果，不覆盖节点生命周期状态。

跨轮复用必须同时满足：节点为 `done`、`survey_status=complete`（长列表被 3 屏上限收口时以 `scroll_capped` 视为 complete）、`pending=0`、`unplanned_actions=0`、计划与恢复对账通过、截图引用存在且图片可解码；`unplanned_regions` 作为 warning 记录，不再单独阻断复用。任一条件失效时改为 `partial` 或 `failed` 并补采，不能只检查 JSON 中有一个截图路径。

每条重复或复用路径至少保存 `source_visit_key`、`visit_key`、`target_id`、`target_visit_key`、`duplicate_of`、本地化 `navigation_path`、`first_navigation_path`、`restore_status` 和 `map_reason`。安全禁止目标只保留父页可见状态，其 `skipped` 原因不计为正常页面截图证据。

页面地图在以下时点采用“临时文件写入后原子替换”：节点创建、`collecting`、计划生成、每个目标完成、页面 `done/partial/failed/blocked`、运行结束。每轮 `page_map_snapshot.json` 保存本轮节点和边的 `new/done/skipped_done/partial/failed/blocked` 变化及原因；新一轮失败不得删除上一次有效证据。

层级和数量上限只用于防止失控，不能静默跳过。当前扩展任务达到第 4 层时，第 5 层入口写为 `skipped + skip_class=depth_limit`；页面数、重进或时间预算耗尽时，将当前目标及尚未执行计划写为 `skipped + skip_class=resource` 或 `failed + skip_class=error`。循环路径仍登记关联边和循环原因。历史清理不得删除仍被 `last_valid_capture` 引用的证据，确需删除时同步把节点改为 `partial`。

#### 5.2.1 每页独立四层扩展

```text
expansion_key = language + "|" + expansion_root_page_key + "|depth=4"
relative_depth = 当前页面在 expansion_root_page_key 扩展链中的层级，起始页为 1
path_depth = 当前完整导航路径的页面数，仅用于诊断
```

- 任意业务页面都可作为扩展起点。只有到达新 `page_key` 的独立页面、独立 Tab/状态页或弹层才使 `relative_depth + 1`；滚动、折叠、轮播、搜索和同页筛选不增加层级。
- 第 1～4 层均执行或复用页面自身覆盖；第 4 层仍完整采集本页和页内交互，第 5 层不得进入。`depth_limit` 是预期边界结果，不是资源不足或失败。
- 页面自身 `nodes[page_key].status` 与扩展任务 `expansions[expansion_key].status` 分开更新。同一节点参与另一个扩展任务时重新计算 `relative_depth`，不得改写页面身份或使已有证据失效。
- 已完成页面在新的扩展任务中可复用已知计划和关联边继续定位后代，但不重复整套预扫描、翻页和自身截图。扩展状态只在实际执行过该 `expansion_key` 时记录，不为所有节点预建组合。
- 不设置全局 `path_depth` 截断；整轮由“我的”范围、`page_key/collecting` 循环阻断、唯一页面数和时间预算收口，完整路径仍逐页保存。

### 5.3 验证计划

每个新页面生成持久化计划，至少包含当前页面身份 `visit_key`、`page_id`、`target_id`、来源、计划动作、所在屏幕、风险级别、证据规则、恢复规则和最终状态。入口实际到达目标页面后，在来源页对应该目标补充 `target_visit_key`；确认重复时再补充 `duplicate_of`。除点击/滑动目标外，每页还登记页面滚屏证据目标，防止只生成入口计划而漏掉页面本身。

```text
plan_key = run_id + "|" + visit_key + "|" + target_id
target_key = SHA256(visit_key + "|" + target_id + "|" + normalized_locator + "|" + planned_action + "|" + expected_view_state)
```

每行还保存 `run_id`、`plan_key`、`target_key`、`parent_plan_key`、`expansion_root_key`、`relative_depth`、`path_depth` 和 `skip_class`。`page_plan.csv` 是本轮“识别目标—执行结果”对账主表；`manifest.csv` 和实际动作记录必须携带同一个 `plan_key`，一个计划可对应多条证据。`parent_plan_key` 指向使当前页面到达的来源入口计划，根页面为空。`target_key` 只用于跨轮比较，不代替本轮唯一的 `plan_key`，也不替代导航关系的 `route_key/edge_key`。

计划动作分为 `scroll_capture`、`click`、`horizontal_swipe`、`open_popup`、`select_safe_option`、`enter_first_screen`、`record_only`、`deferred`、`restore`、`restore_only` 和 `forbidden`。动作分级由目标名称和控件语义共同判定，输出 `allow_entry / deferred / hard_blocked` 三档：`enter_first_screen` 与普通 `click` 属于 `allow_entry`；`record_only` 只保存父页或当前状态，不切换；`deferred` 在页面采集阶段只登记、状态记为 `deferred`，本轮全部页面完成后按导航路径重放并截取首屏，最终收敛为 `ok/failed/skipped`；`forbidden` 直接形成有原因的 `skipped`。安全动作初始为 `pending`，执行后只能收敛为 `ok/failed/skipped`（`deferred` 为轮末前的中间态）。计划行新增 `label` 列，用于直接从 `page_plan.csv` 追溯 `auto_003` 这类动态目标对应的实际文案。

证据规则在计划中预先定义，不能执行后用截图总数反推覆盖率：

| 目标类型 | 预期证据 |
| --- | --- |
| 可滚动页面 | 从顶部到页面终点的一张或多张连续屏幕；长列表最多 3 屏 |
| 下拉/选择器 | 一张展开态及前三个安全选项的结果图，不足三个则覆盖全部 |
| 首页轮播 | `1/3、2/3、3/3` 三张不同状态图及恢复记录 |
| 点击无跳转 | 无新页面截图，但必须有 `no_change` 动作结果 |
| 重复/跨轮复用页面 | 无新截图，但来源页目标必须有 `target_visit_key`、`duplicate_of`、`map_reason`；实际进入后复用的还必须有原屏恢复记录 |
| 安全首屏 | 首个说明页或空白表单截图、动作结果及返回恢复证据，不含填写或提交 |
| 延迟目标 | 本轮末尾按导航路径重放后的退出/注销首屏截图及 `ok/failed/skipped` 结果，不含最终确认 |
| 只记录/不可逆目标 | 父页可见状态及 `record_only` 结果或 `skipped` 原因，不执行禁止点击 |

### 5.4 按计划执行

```text
确认 survey_status=complete，计划已保存，初始状态已恢复
先完成页面逐屏截图计划，再回到顶部
首屏截图落盘后立即对齐采集项：用同一帧的控件树与 OCR 重新枚举可见交互项，
  与已登记计划比对；新增安全项补入计划（source=align_first_screen）后再执行，
  固定项未在首屏出现时保留待后续屏核销；对齐结果写入 first_screen_alignment 并进入覆盖报告
按计划顺序处理每个目标：
  重新读取目标位置，禁止使用已失效控件对象
  执行前读取前台包名；不在目标 App 时禁止动作并恢复
  hard_blocked 目标写 skipped，不点击
  deferred 目标只登记为 deferred，不在此阶段点击
  其余目标执行已登记动作并记录实际行为
  点击后再次读取前台包名；越界时禁止 survey 和点击并恢复
  若到达新页面 / Tab / 弹层：
      先按 route_key/page_key 查询持久页面地图
      在来源页目标记录 target_visit_key 和对应 edge_key
      新页面递归执行预扫描、计划、恢复、采集
      重复或跨轮完成页面登记 duplicate_of + map_reason，不重复执行
      返回父页面只执行 restore_only(screen + view_state)，不重新 survey 或翻页
  若无变化：
      写 no_change，不伪造进入成功
  保存证据并更新该 target_id 的最终状态
  若发现未登记区域：
      暂停当前页后续动作，补充预扫描和计划后再继续
```

- 同一入口只展开一次；不同入口是否重复由持久关联边指向的 `target_page_key` 或实际到达页面的 `target_visit_key` 决定，不得仅按标题、布局或当前屏文本指纹跳过。
- 每次从子页面或弹层返回后重新定位下一个目标，不得继续使用旧控件对象；返回后的控件读取只服务于恢复和下一个目标定位，不得重新生成父页完整采集计划。
- 当前扩展任务的相对第 4 层只完成本页预扫描、滚屏和页内交互，不再进入相对第 5 层；SC-05 交易详情同样按所属 `expansion_root_key` 计算层级，不使用全局 `path_depth` 截断。
- 时间、截图或页面预算耗尽前，必须把剩余计划目标写成明确结果并标记页面未完成，禁止直接 `break` 后按成功结束。

### 5.5 原屏与页面状态恢复

保存 `path_labels + parent_signature + screen_index + view_state` 作为恢复上下文。`view_state` 按页面包含当前 Tab、客户范围、月份、筛选条件、余额显隐、轮播初始序号；交易列表另保存当前记录锚点。

1. 预扫描结束后先恢复 `initial_view_state` 并回到顶部，正式执行前校验关键状态。
2. 子页面或弹层优先通过页面内退出或单次系统返回离开；实际进入的重复页面同样执行返回和来源原屏恢复。恢复路径调用 `restore_only` 并保留 `parent_page_key + screen_index + view_state`，不得重新调用 `visit_page()` 触发父页预扫描和翻页。
3. 返回后确认父页面，恢复进入时的 Tab、客户范围、月份和筛选条件，再回到顶部并执行 `screen_index - 1` 次同距离上滑。
4. 比较当前指纹、查询条件和记录锚点；任一关键状态不符时不继续点击其他记录。
5. 余额眼睛只改变本地显隐时，采集切换态后立即恢复；轮播采集后按指示序号恢复初始位置。
6. 失败时从“我的”按原路径重进，再恢复查询状态和目标屏幕；需要重启时保留登录态并重新识别。
7. 仍失败则保存异常截图和 `failed` 清单，明确是页面返回失败、查询状态恢复失败还是滚动位置恢复失败。

### 5.6 页面完成与数量对账

新采集页面只有同时满足以下条件才能标记 `complete/done`：预扫描完成、所有计划目标已有最终状态、`pending=0`、未登记执行动作数为 0、有效截图及证据关联完整、要求的恢复成功；未规划区域只作为 warning 列入覆盖报告和最终说明，不单独阻断页面完成。延迟目标在页面阶段为 `deferred`，轮末必须收敛，轮末仍残留的 `deferred` 计入未完成项。已确认重复或跨轮复用的目标页面不生成完整采集计划，也不单独参与目标页的 `complete` 判定；其来源入口必须在来源页计划中通过 `target_visit_key`、有效 `duplicate_of`、明确的 `skipped=重复页面/已完成页面`、`map_reason` 和需要的原屏恢复结果完成核销。循环入口则通过 `target_visit_key`、`skipped=循环页面`、正在采集路径关联和恢复结果核销。

逐目标执行 `planned = ok + failed + skipped` 对账；安全策略、具有有效 `duplicate_of` 的重复页面和第 4 层 `depth_limit` 属于已处理，循环阻断属于已处理的安全跳过，资源限制、异常和预扫描不完整导致的 `skipped/failed` 同时计入未完成项。所有计划、动作和证据先按 `plan_key` 连接，再按 `target_key` 做跨轮比较；旧 `(language,page_id,target_id)` 只保留为展示和诊断信息，不再充当唯一对账键。

覆盖报告分别生成 `pages[visit_key]` 与 `expansions[expansion_key]`：前者判断页面自身识别目标和证据是否完整，后者判断指定起点相对第 1～4 层的节点和关联边是否完整。节点 `done` 不能自动使其所有扩展任务为 `done`，扩展任务完成也不能替代其中某个失败页面的补采。

截图数与目标数分别统计，不要求机械相等。`coverage_report.json` 必须能按证据规则解释“一个目标多张图”、“多个不可逆目标共用父页证据”、“无跳转目标没有新页面截图”和“共享详情页只在首次路径截图”，无法解释的差异使验收失败。

### 5.7 延迟动作队列

1. 发现阶段把目标分为 `allow_entry`、`deferred`、`hard_blocked` 三档。退出登录、注销账号、结束会话等会终止当前会话或账号态的动作进入 `deferred` 队列，计划动作 `deferred`，页面执行阶段不点击。
2. 本轮所有页面采集结束（含最后一级入口返回）后，才统一执行队列：先普通延迟项，再注销类，最后退出登录类，避免退出后无法继续取证。
3. 重放使用计划行的 `navigation_path`：回到“我的”首页，按中间层级逐段点击定位，再点击延迟目标；目标不在首屏时允许最多 3 屏上滑查找。
4. 点击后只截取首屏证据，不点击任何“确认退出/确认注销”类最终按钮；随后返回来源页。退出登录类点击后不再尝试恢复首页。
5. 延迟项最终状态只能是 `ok/failed/skipped` 并带证据或可读原因；不允许在本轮结束时保留 `deferred`。

### 5.8 增量补采与范围过滤

1. 补采轮以最近一轮 `coverage_report.json` 的 `incomplete/failed/partial` 项和页面地图缺口为输入，只执行缺口清单；已完成且证据有效的节点按 5.2 直接 `skipped_done`，不重新预扫描、不重新截图。
2. `CRAWL_ROOTS` 限定一级入口；`CRAWL_ROOTS=home` 只采“我的”首页固定项（消息、客服、设置图标、钱包、余额显隐、轮播三态、头像/用户名/徽标探测），不进入任何一级入口。
3. 设置 `CRAWL_ROOTS` 时：含 `home` 的轮次只采“我的”首页固定项，一级入口和动态卡片写 `skipped + skip_class=scope`；不含 `home` 的轮次只进入列出的一级入口，首页固定项和动态卡片同样写 `scope`。`scope` 不计漏采、不产生截图，已完成的子页仍按 `skipped_done` 复用。
4. 补采轮覆盖报告必须写出 `root_filter` 和 `scope` 跳过清单；`complete` 恒为 `false`，只用于缺口收敛，不用于整体验收。
5. 补采轮同样原子更新 `page_map.json` 和本轮快照；本轮失败不得删除历史有效证据。整体完成以缺口清单清零、各轮证据合并后覆盖完整为准。
6. `CRAWL_DEFERRED` 控制轮末延迟项：`auto`（默认）仅在无 `CRAWL_ROOTS` 的全量轮执行；范围补采轮保留 `deferred` 不点击，由最后收尾轮显式设置 `CRAWL_DEFERRED=1` 执行。中间轮残留的 `deferred` 在覆盖报告中列为待收尾项。

## 6. 交互策略

| 类型 | 判定与动作 | 去重/恢复 | 需求 |
| --- | --- | --- | --- |
| 固定行式入口 | 预扫描以固定别名优先，几何和动态文本补充，先生成计划再点击 | 每页每入口一次；固定项未命中记失败 | FR-01、FR-03、SC-04 |
| 无文字图标 | 预扫描结合固定区域、控件几何、可点击属性/最近可点击祖先登记 | 无变化记录一次；有变化先预扫描新页面再截图 | FR-03、SC-04 |
| 下拉/选择器 | 父页预扫描登记打开动作；打开后面板独立预扫描和滚屏 | 预扫描后保存展开一图；前三个安全选项各一图；恢复原值 | FR-04 |
| 筛选/查询 | 只允许计划中的展示条件选项和确认动作；结果新增内容先补充预扫描 | 采集面板与结果；重置/关闭并恢复初始条件 | FR-04、FR-05、SC-05 |
| 按钮 | 预扫描结合文本语义和几何登记，结果页面/弹层先预扫描 | 安全按钮截图；业务最终确认只截展开态 | FR-05、SAFE-01～03 |
| 横向 tab | 预扫描登记同行至少三个短标签及选中态；切换后逐 Tab 预扫描 | 当前项不重复点击；其余逐项采集并恢复 | FR-06 |
| 轮播 | 预扫描读取 `n/m` 并登记区域，执行时结合指示序号和区域图像变化滑动 | 首页固定三张；其他最多四张；恢复初始位置 | FR-07、SC-04 |
| 交易记录行 | 预扫描通过整行及右侧箭头登记全部记录，金额和状态不单独点击 | 每条进入一次以核验身份；同业务详情登记 duplicate_of，新详情才预扫描采集；返回原 Tab、查询条件和原屏 | SC-05、FR-08、AC-13 |

下表所有动作均受第 5 章身份核验、预扫描门禁和全局去重约束。所有点击类别共用同一套三档分级（`allow_entry / deferred / hard_blocked`），不允许出现“行入口已拦截、按钮探测却可点击”的规则差异，也不允许因入口名称而整页跳过。

### 6.1 “我的”首页固定目标

首页必须先完成整页只读预扫描，将下列固定目标和动态发现目标全部写入计划并恢复初始状态，再开始首页截图和任何点击/滑动；不得只调用页面截图而跳过首页计划。

1. 顶部消息铃铛、客服耳机、设置齿轮分别定位和处理；设置复用 `settings`，消息和客服不得因没有文字而漏掉。
2. 钱包眼睛采集显隐两个状态并恢复原始状态；钱包右侧箭头作为 `wallet` 独立入口进入，不能与眼睛合并成一次点击。
3. 存款、取款、转账、资金明细和会员俱乐部按固定 ID 核销。会员俱乐部优先点击“查看”；只有横幅主体也具备可点击特征时才补一次探测，同一目标页面按重复关系记录。
4. 代理专区、我的信息、跟单社区、积分商城根据选中态处理；当前 Tab 保存当前状态，其余 Tab 点击切换，不重复点击当前项。
5. 代理专区的 `IB臻享计划、佣金管理、客户管理、客户订单、客户资金、开户链接` 由固定注册表核销；自动发现的新增行追加到清单，不能替换固定六项。
6. 头像、用户名、会员徽标、IB 徽标分别执行一次安全探测。无页面变化时保存 `skipped=点击无跳转` 及动作记录；有变化时先核验 `target_visit_key`，新页面才预扫描采集，重复页面登记 `duplicate_of`，随后返回。
7. 底部“行情、图表、订单、发现”不点击，“我的”已选中时不重复点击。

### 6.2 首页三图轮播算法

以下算法只在首页预扫描完成、轮播区域及三个预期状态已写入计划、页面已恢复初始状态后执行。预扫描只读取 `n/m`，不提前横滑或保存轮播正式截图。

```text
读取初始指示序号 initial_index（有效值为 1、2、3）
states = {}
在有限尝试次数内循环：
  等页面稳定，读取当前指示序号和轮播区域图像哈希
  若当前序号不在 states：保存 carousel[当前序号] 截图并写入 states
  若 states 已包含 1、2、3，停止滑动
  在轮播区域横向滑动一次
  若指示序号和区域图像均未变化，记录滑动无效并停止
若缺少任何序号：为缺失状态写 failed
按指示序号滑动恢复 initial_index，并保存恢复校验结果
点击轮播卡片一次：
  有安全跳转则先核验 target_visit_key；新页面预扫描采集，重复页面登记 duplicate_of；随后返回；无变化则记录“点击无跳转”
```

- 轮播变化必须结合指示序号和轮播区域图像哈希判断，不能只依赖页面文本指纹，因为三张图可能共用相同文字。
- 初始截图可以是 `3/3`，不要求先假设位于 `1/3`；最终必须回到实际初始序号。
- 滑动尝试设置上限以防止死循环，但上限只能产生明确失败，不能把缺少 `1/3、2/3、3/3` 的运行记为通过。

### 6.3 资金记录列表页算法

页面通过“全部客户”标题/切换图标、存款/取款/转账 Tab、月份控件和筛选图标共同识别；仅匹配单个文本不直接判定为该页面。

1. **初始预扫描**：保存当前 Tab、客户范围、月份、筛选条件和列表顶部指纹；当前 Tab 从顶部只读预扫描（长列表最多 3 屏），登记固定控件和该范围内的交易行，此阶段不截图、不点击。
2. **客户选择器**：父页面计划完成后才可点击“全部客户”标题或切换图标；面板打开后先在面板内只读预扫描到底，再采集展开态。关闭或重新选择原客户范围，确认恢复“全部客户”，不把客户筛选误作账号切换。
3. **逐 Tab 处理**：依次核销 `deposit`、`withdraw`、`transfer`。当前 Tab 不重复点击，其他 Tab 按计划切换；每次切换后先独立预扫描（长列表最多 3 屏）并恢复顶部，再执行该 Tab 的月份、筛选、逐屏截图和交易详情，不能只验证存款 Tab。
4. **月份选择器**：打开后先完成选项面板预扫描，再保存展开态；按 FR-04 采集前三个安全选项的结果，最后恢复该 Tab 的原始月份。
5. **筛选器**：面板打开后先预扫描，再保存展开态，验证安全筛选项、纯查询结果及重置/关闭状态。查询结果出现新记录时先补充预扫描和计划；只有不改变业务数据的筛选确认可以执行，完成后核对初始筛选条件。
6. **逐屏和逐条记录**：每个 Tab 必须先完成基线列表在 3 屏上限内的只读预扫描并恢复顶部，再按计划逐屏截图、逐条进入详情。进入后先以交易业务标识核验 `target_visit_key`，新详情才预扫描和截图，已在其他模块完整采集的详情只登记 `duplicate_of`。部分露出的行在预扫描时先滚动到完整可见；从详情返回后恢复原 Tab、月份、筛选、滚屏位置和记录锚点，再处理下一条。
7. **补充发现**：正式执行中出现预扫描未登记的记录或控件，暂停当前 Tab 后续动作，补充预扫描和计划后再继续，禁止直接点击。
8. **记录去重**：优先读取稳定交易 ID；无法取得时以记录类型、日期时间、金额、状态及重复序号组成 `business_key`，保留业务数字，列表位置和来源查询条件不参与详情的全局去重。相同业务详情跨模块只完整采集一次，不同记录即使布局相同也不得合并。
9. **非按钮区域**：金额、状态文字不单独点击；月份标题和“本月无记录”只有可点击属性明确时才探测。页面没有明确横向轮播，不额外执行横滑。
10. **最终恢复**：三个 Tab 完成后恢复进入页面时的 Tab、客户范围、月份和筛选条件，再通过左上角返回箭头回到父页面。

交易详情只保存只读状态。出现“继续支付、取消订单、重新提交、上传凭证”等控件时，仅记录其所在页面或展开态，不点击；测试数据会变化，因此验收核销“实际发现的全部记录”，不把截图中的三条示例记录写成永久固定条数。

### 6.4 消息中心导航、身份与恢复

- 消息主页 `business_key=home`；重要通知、资金动态、账户动态、品牌动态分别使用 `business_key=category:important/funds/account/brand`。四个入口的 `expected_page_id` 虽都为 `mine.notifications`，但业务键不同，因此形成不同 `page_key`。
- 分类详情 `parent_kind=notification_category` 时不再登记当前分类入口或消息正文点击目标，只执行本列表的纵向覆盖与关联审计，避免 `A → B → B` 自递归。
- 未读数、金额和日期按页面类型归一化后再比较恢复指纹；列表内容和分类身份仍须保留，不能把所有数字统一删除。
- 消息主页及分类详情顶部中央标题只作为页头，不登记为入口，也不计入 `unplanned_regions`；未读总数导致标题宽度变化时仍按中央几何区域识别。其他可交互区域继续复用统一 `region_registered()` 审计，禁止另写一套宽松过滤。
- 分类返回消息主页走 `restore_only`，不得重新调用 `visit_page()`。再次遇到消息入口或分类入口时先查询 `route_key/page_key`，完成且证据有效就直接复用，不重复整套翻页。
- 消息中心属于长列表，与全部列表页共用最多 3 屏的纵向上限；达到上限仍有新内容时写 `scroll_capped` 提示并按已采证据完成，不再以“预算耗尽/未到底”判页面失败。

### 6.5 安全管理动作分级

安全入口按“入口进入取证优先、页内不可逆动作拦截”执行，不得把整个入口名称直接等同于禁止进入。

| 入口 | 页面级动作 | 证据 | 页内限制 |
| --- | --- | --- | --- |
| 修改密码 | `enter_first_screen` | 表单首屏及返回恢复 | 可输入占位内容；禁止保存、提交、发送验证码 |
| 手势解锁 | `enter_first_screen` | 手势设置首屏及返回恢复；需图案验证时只保留入口截图和原因 | 禁止绘制或设置图案、禁止切换开关 |
| Google Authenticator | `enter_first_screen` | 第一个说明页及返回恢复 | 禁止启用、绑定、扫码、验证码和确认 |
| 注销账号 | `deferred` | 本轮末尾的注销入口首屏 | 禁止点击任何注销确认、禁止填写注销资料 |
| 客服 | `enter_first_screen` | 客服首屏及返回恢复 | 禁止发送消息、上传附件 |
| 返回 | `restore` | 来源页身份和恢复状态 | 恢复失败立即停止后续点击 |

页内 `hard_blocked` 继续拦截提交类按钮，但不能覆盖入口级 `enter_first_screen`。截图只证明到达首屏，不得被解释为完成密码修改、认证器绑定、注销或客服消息发送。

### 6.6 客服与常见问题页统一发现

#### 6.6.1 20261107_171829 轮次漏采调查

旧轮次 `page_plan.csv` 对 `mine.customer_service` 只生成 `screen[1]`、`screen[2]`、`screen[3]` 三个 `scroll_capture` 目标；`manifest.csv` 也只有三张“纵向逐屏截图”，没有任何页内功能执行证据，来源页“我的 > 客服”最终为 `failed=页面计划、动作或恢复未完成`。因此该轮次不能表述为客服页面采集或验收通过。

三张真实截图显示目标是“常见问题”页，而不是只有消息气泡的聊天会话。三张图合并后至少可见 **19 个交互点**：返回 1、搜索 1、下拉选择器 2（`分类中文`、`kk-cn`）、问答折叠项 14、人工客服 1。问答项包括首条特殊字符问答，以及 `11`、`新增一级分类`、`app交易`、`中文分类0611-游客`、`中文分类0611-客户`、`321`、`无二级分类`、`H-一级分类Aaa`、`H-全部一级分类Asd`、`H-一级分类B`、`中文分类`、`xlh_CS`、`一级分类`。`1条未读` 是人工客服按钮的状态角标，不单独计为入口。第三屏底部仍有问答项，三张图本身不能证明列表已经到底；按长列表口径，最终数量以 3 屏上限内的只读预扫描结果为准，超出部分记 `scroll_capped` 提示，不能把 14 写成永久固定条数。

直接原因不是控件树或 OCR 完全无法扫描，而是扫描后的目标被页面级豁免过滤，形成“取数—发现—计划—执行—审计”断链：

| 位置 | 旧行为 | 直接后果 |
| --- | --- | --- |
| `survey()` | 已调用 `page_items()`、`discover_generic()` 和 `discover_dynamic()` | 页面确实进行了统一取数，问题发生在后续过滤，不应归因为未扫描 |
| `discover_generic()` | 对 `mine.customer_service` 跳过 `discover_cards()` | 卡片/问答折叠项不进入计划 |
| `discover_dynamic()` | 对客服页直接 `return` | 普通按钮、导航行和可点击父节点均不登记 |
| `interactive_item()` | 对客服页 OCR 项整体返回 `False` | OCR-only 功能既不进入发现，也不进入 `unplanned_regions`，覆盖审计同步失效 |
| `fixed_targets_for()` | 只登记从“我的”进入客服的入口，没有客服页内固定目标 | 通用发现被排除后没有任何兜底目标补偿 |

根因是把“客服会话不得输入、不得发送”的安全例外错误扩大成“客服整页不做功能发现和 OCR 审计”，同时把“常见问题”和“人工客服会话”混用同一豁免规则。安全限制应作用于具体危险控件和动作，不能取消整个页面的统一发现义务。

#### 6.6.2 修正后的发现、执行与恢复规则

1. **拆分业务身份**：常见问题列表与人工客服会话分别识别；即使复用 `page_id=mine.customer_service`，也使用独立 `business_key=faq/conversation` 和不同 `page_key`。常见问题按完整功能页采集，会话页只进入首屏，不输入、不发送。
2. **取消整页发现豁免**：客服相关页面仍执行统一 `page_items()`、控件树与 OCR 补充、通用发现、动态按钮/行入口发现和 `unplanned_regions` 审计。不得再以 `page_id` 为由让整页 OCR 项直接失效。只允许把已确认的聊天正文、消息气泡和中央页头分类为非独立入口，并记录排除原因。
3. **搜索**：登记搜索图标和搜索页/弹层；在常见问题搜索框中使用安全关键词 `app`，采集结果后清空并恢复初始列表。该搜索输入不等于在人工客服会话中输入消息。
4. **选择器**：`分类中文` 与 `kk-cn` 分别打开、独立预扫描并保存展开态。安全展示选项按通用规则验证并恢复原值；若确认 `kk-cn` 会切换 App 全局语言，则只保存展开态和当前值并关闭，不切换语言。
5. **问答折叠项**：纵向预扫描按长列表上限最多 3 屏，登记该范围内的全部问题，不要求把超过 3 屏的剩余问答全部展开；每项执行展开、截图、收起；重复文案用归一化问题文本加稳定业务标识或同页序号区分。首条进入时已展开，完成后必须恢复该初始展开状态，其余项恢复进入前状态。
6. **人工客服**：作为独立 `enter_first_screen` 目标进入会话首屏，保存页面和返回恢复证据；输入框、发送、附件等动作分别标记 `forbidden/record_only`，不得点击发送。未读角标只作为按钮状态记录。
7. **返回与覆盖门禁**：返回目标所属来源页并验证 `restore_status`。每个发现目标必须收敛为 `ok/failed/skipped` 并具有对应证据或可读原因；只有三张逐屏图而搜索、选择器、问答、人工客服等目标没有计划或结果时，页面必须为 `partial/failed`，不得记 `done`。

本次调查只确认根因并修订设计；上述三处整页特判在调查时仍存在于实现基线中，必须完成代码同步和回归后才能声明问题已修复。

#### 6.6.3 人工客服会话内容门禁（20261110 轮次错图修正）

`20261110_095125` 轮次的 `我的 > 客服 > 人工客服/001_逐屏.png` 实际 OCR 为 `请输入问题 / 取消 / 热门问题 / 有帮助 / 没帮助`，属于常见问题搜索态，不是人工客服会话。真实人工客服页面为聊天会话，包含 `在线客服`、`请输入内容`、`结束会话` 和 `Aa` 等特征。错图根因是点击「人工客服」后 `is_overlay()` 以“旧文案保留比例 ≥50% 且指纹变化”把新页面误判为弹层，登记成 `mine.customer_service.popup.faq.human` 并截图成功；此后跨轮按 `done` 复用该错误证据。

修正规则：

1. **内容门禁**：`kind=customer_service_conversation` 的目标点击后先轮询等待会话特征，中文至少命中 `在线客服`、`请输入内容`、`结束会话` 中的 2 项，日文使用对应会话特征；未命中不得通过，目标记 `failed`（如 `未进入人工客服会话`），禁止写入 `ok` 或产生有效截图。
2. **FAQ 搜索态排除**：页面同时出现 `热门问题`、`有帮助`、`没帮助`、`请输入问题` 等常见问题搜索态特征时，判为 FAQ 页面/弹层，不得作为人工客服会话证据。
3. **弹层判定豁免**：会话页由导航进入，即使保留较高旧文案比例也不得按 `is_overlay()` 判为弹层；该 `kind` 一律按导航页登记，只采集首屏并执行返回恢复。
4. **证据失效清理**：已落盘的错误会话证据（截图目录、`page_map.json` 节点及相关边）必须删除后重采；后续只接受通过内容门禁的新证据。
5. **入口前置状态**：执行人工客服前必须确认页面处于常见问题列表而非搜索态；搜索动作无论成功或失败都必须退出搜索页并校验恢复，避免在搜索页上继续点击人工客服。
6. **会话页只采首屏**：会话页属于终端页，只采集首屏，不做纵向滚动预扫描、不登记聊天内容中的动态目标、不点击「结束会话」等状态变更入口；采集后按返回路径恢复来源页。
7. **返回恢复锚点**：客服页恢复校验必须包含常见问题页稳定文案（如 `常见问题`、`人工客服`），不能只依赖无字搜索图标；返回 `我的` 失败时优先点击底部「我的」标签回首页，重启重放路径前必须先等待并确认回到 `我的` 首页，避免级联跳过一级入口。
8. **恢复判定与补充返回**：恢复核验优先用页面锚点，锚点不足时退回整页相似度；一次返回未恢复且前台仍在本应用时，允许再退一层以处理残留弹层，仍失败才重启重放，不得直接消耗重启预算。
9. **终端页审计豁免**：会话页等终端页不做未规划区域审计，避免页头等动态元素把页面卡成 `partial`。
10. **审计证据口径**：未规划区域只统计可证明可点击的控件（控件树 `clickable` 或树节点行几何）；纯 OCR 文本不作为未规划交互证据，避免只读资料页被误判。
11. **子页不预置下拉**：进入子页时页面本来就在顶部，预扫描不得先执行下拉回顶手势；下拉回顶仅用于「我的」首页，避免在子页触发下拉刷新/回弹并拖慢采集。子页从第 1 屏直接开始，后续用上滑翻屏。

## 7. 安全设计

### 7.1 三档分级

- `hard_blocked`（任何情况下不执行）：保存、提交、发送验证码、买入/卖出、下单、开平仓、支付、购买、实际入出金和转账、继续支付、取消订单、重新提交、上传凭证、删除确认、清空、清除数据/缓存、卸载、强制停止、停用/禁用、切换语言。
- `deferred`（本轮末尾执行，仅首屏取证，不确认）：退出登录、注销账号、结束会话。
- `allow_entry`（必须进入首屏取证）：修改密码、重置密码、手势解锁、Google Authenticator、绑定/解绑、删除数据入口页等全部其余入口，以及各类说明页、表单页和状态开关页。
- 表单：允许输入占位测试内容验证控件，禁止保存、提交、发送验证码；禁止使用真实账号、密码、验证码、金额和客户资料。
- 权限：不授予新增系统权限；出现系统权限弹层只关闭并记录。

### 7.2 页面与动作分离

- 存款、取款、转账等需求明确包含的一级页面允许打开和截图，但禁止继续执行资金动作。
- 客户选择器只用于记录查看范围，不等同于登录账号切换；只采集安全展开态并恢复原客户范围。
- 筛选、查询类确认只有在其效果仅是刷新当前列表、不写入业务数据时才可执行；执行后必须恢复初始条件。名称是“确认”不能单独作为安全依据。
- 首页头像、徽标和轮播卡片的安全探测只执行一次；出现资金、账号、资料或订单表单时仍进入首屏取证，但不执行提交类动作。
- 修改密码、Google Authenticator、手势解锁、绑定/解绑按 6.5 进入首屏取证；任何允许进入的表单仍禁止保存、提交和发送验证码。
- 退出登录、注销账号、结束会话按 `deferred` 进入轮末队列，按 5.7 重放取证，不点击最终确认。
- 通知、隐私、手势及其他账户状态开关按 `record_only` 处理，只记录“开启/关闭”等状态，不得作为普通卡片点击。
- 点击前通过 `dumpsys window` 读取前台包名；不在目标 App 时不执行动作并先恢复。点击后再次检查，若进入系统设置等外部应用，立即恢复目标 App 和来源页，目标记 `skipped=外部应用禁入`；外部页面不得 survey、截图遍历或点击任何系统按钮。恢复失败记 `failed` 并停止后续动作。
- 卸载、清除数据、清除缓存、强制停止、停用、禁用及对应日文系统操作一律列入危险词，不得通过固定坐标兜底执行。
- 权限弹层、业务确认弹层、查询筛选面板分别判定；不得把“关闭弹层”写成“确认操作”，也不得把查询确认写成业务提交。
- 日志只记录入口名和动作，不记录凭据内容。

## 8. 输出与清单

目标目录：

```text
app_page_captures/lang/<语言>/
├─ page_map.json
├─ page_map.mmd
└─ <时间戳>/
   ├─ screenshots/
   │  └─ 01_我的/<导航层级>/<交互目录>/<序号_状态>.png
   ├─ errors/
   ├─ page_plan.csv
   ├─ manifest.csv
   ├─ page_map_snapshot.json
   ├─ ocr_text.csv
   ├─ local_report.json
   └─ coverage_report.json
```

`page_plan.csv` 目标字段：

```text
run_id, language, visit_key, page_id, target_id, label, target_visit_key, duplicate_of,
plan_key, target_key, parent_plan_key, expansion_root_key, relative_depth, path_depth,
navigation_path, source, planned_action, screen_index, risk, evidence_rule,
restore_rule, survey_status, status, skip_class, error, edge_key, map_reason
```

计划在正式截图前生成并落盘，`planned_action` 表示预扫描登记的计划动作，`manifest.csv.action` 只记录实际执行动作。一个计划目标可关联多条截图/动作证据，二者以本轮唯一的 `plan_key` 对账，跨轮通过 `target_key` 比较同一采集点。`visit_key` 是计划或证据所属的当前页面身份；`target_visit_key` 是入口实际到达的目标页面身份；`duplicate_of` 指向该目标首次完整采集的证据引用。

`manifest.csv` 目标字段：

```text
screenshot, run_id, language, visit_key, page_id, target_id, label, target_visit_key, duplicate_of,
plan_key, target_key, parent_plan_key, expansion_root_key, relative_depth, path_depth,
navigation_path, source, action, screen_index, status, restore_status, skip_class,
fingerprint, error, edge_key, map_reason
```

- `page_id` 用于跨语言配对，`target_id` 对应固定目标注册表或动态发现目标；`plan_key` 是本轮计划与证据的唯一对账键，`target_key` 用于跨轮目标比较。读取端按字段名解析，避免依赖列位置。
- `visit_key` 始终表示本条计划/证据所属的当前页面；`target_visit_key` 只表示该入口实际到达的目标页面。凡实际到达新页面、Tab 或弹层均填写后者，未跳转及纯页内动作留空；不能把来源页身份写入 `target_visit_key`，也不能用目标页身份覆盖来源页的 `visit_key`。
- `duplicate_of` 仅在注册表状态为 `done` 的重复来源记录中指向首次完整采集的有效证据；循环来源记录必须填写 `target_visit_key`，并在 `error` 中记录循环原因及正在采集的 `first_navigation_path`，其 `duplicate_of` 留空。
- `source` 统一区分发现来源 `tree`、`ocr`、`fixed`；`row/icon/tab/popup/filter/button/carousel/record` 等交互类型保留在 `kind` 或 `metadata_json`，`retry/errors` 作为执行上下文记录，不与发现来源混用。
- `restore_status` 记录 `ok/failed/not_required` 及必要的状态说明；恢复失败不能只写在运行日志中。
- 计划创建和每次状态变化立即写入并 flush；证据清单也逐条 flush，异常中断后仍能追溯到最后一个计划目标和实际动作。
- `ok` 必须有真实文件；`failed` 尽量有异常截图；`skipped` 必须有可读原因。没有截图的固定目标未命中同样必须写入清单。
- `coverage_report.json` 汇总预扫描状态、计划目标数、各最终状态数、各 `skip_class` 数、未登记动作数、未规划区域数、一级入口、固定目标、各交互类型、地图复用数和未配对项。
- `coverage_report.json.reconciliation.pages[visit_key]` 保存 `planned/ok/failed/skipped/pending/unplanned_actions/unplanned_regions`，以及 `missing_result_plan_keys/missing_evidence_plan_keys/orphan_result_keys`，并按证据规则保存预期截图数、实际截图数和差异解释；任一无法解释的差异使验收失败。`depth_limit` 目标按预期边界单独统计，不要求目标页截图。
- `coverage_report.json.reconciliation.expansions[expansion_key]` 保存扩展起点、深度上限、各 `relative_depth` 的节点/关联边数、页面自身覆盖引用、第 4 层边界目标和未完成原因；不得只凭完整 `path_depth` 或节点 `done` 判定四层扩展完成。
- `coverage_report.json.dedup` 保存唯一 `visit_key` 数、各地图状态、完整采集数、重复来源数、跨轮复用数、循环阻断数和失败重试数，并保留 `visit_key → first_capture_ref + last_valid_capture + aliases` 映射。每个成功 `visit_key` 在同一轮只能有一个完整采集引用，当前 `last_valid_capture` 唯一但历史证据可保留多轮；重复来源的 `target_visit_key` 必须命中地图，所有非空 `duplicate_of` 必须指向有效完整采集证据，同模板不同业务键不得合并。
- `coverage_report.json.fixed_targets` 逐项保存目标状态；`carousel` 保存 `expected=[1,2,3]`、实际状态、初始序号和恢复序号；`funds_records` 按 Tab 保存预扫描记录数、滚屏数、详情完成数及查询状态恢复结果。
- 历史清理由独立命令完成，不在采集脚本中隐式删除历史结果。不得删除仍被持久地图 `last_valid_capture` 引用的证据；确需删除时同步把对应节点改为 `partial`，其余未引用历史可按每种语言最近两次运行保留。

### 8.1 Mermaid 页面地图生成

- 每种语言由 `page_map.json` 自动生成同目录 `page_map.mmd`，使用 `flowchart LR`；JSON 是唯一事实源，禁止手工只改 Mermaid 后作为采集依据。
- Mermaid 节点 ID 使用 `p_` 加 `SHA256(page_key)` 的稳定短哈希，显示名称使用页面标题及 `done/partial/failed/blocked` 状态；节点 ID 不使用中文、竖线或导航路径，避免语法和跨轮不稳定。
- 关联边按 `source_page_key → target_page_key` 输出，边标签使用入口文案和 `target_id`；多入口指向同一节点时保留多条边，循环边也正常展示。
- 每个有有效证据的节点输出一条 `click <node_id> "<file:///绝对截图URI>" _blank`。JSON 保存相对于语种目录的证据路径，生成 Mermaid 时转为绝对 `file:///` URI；节点默认链接首张有效截图，全部翻页和状态图仍通过 JSON 证据列表及 `manifest.csv` 追溯。
- 没有有效截图的节点不生成虚假链接，并显示对应状态。Mermaid 阅读器需允许链接打开；即使阅读器禁用超链接，`.mmd` 仍必须能正常解析渲染。
- 每次持久 JSON 原子更新后重新生成 Mermaid；本轮 `page_map_snapshot.json` 记录新增/复用节点、关联边、状态和原因，供失败与补采审计。

## 9. OCR 与多语言对照

### 9.1 识别

- 中文使用 `ch_sim + en`，日文使用 `ja + en`。
- 保存识别文本及其来源截图、`page_id`、导航路径；需要展示异常候选时保留文字边界框。
- 单张识别失败写入错误记录并继续其他图片，最后汇总失败数。

### 9.2 配对和异常候选

1. 优先按确定的 `page_id` 配对。
2. 临时 ID 或映射缺失的项进入待复核，不强行匹配。
3. 分别输出“仅中文有”和“仅日文有”，避免只分析路径交集。
4. 日文结果中的连续中文片段进入残留候选；品牌、用户名等进入人工复核。
5. 文字边界触及屏幕/控件边缘、双语识别长度差异异常或文字缺失时生成疑似截断/重叠候选。
6. OCR 只生成候选，最终视觉结论必须回查原图。
